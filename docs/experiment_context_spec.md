# Experiment Context Format Specification

ResearchGroup v2 requires an initial state definition to bootstrap the multi-agent optimization loop. This is defined in an `experiment_context.md` file (e.g., `research_group_timesfm_expt.md`). 

The context file must serve as the ground truth for the agents, defining the boundaries of the environment, the metric to optimize, and the tools available.

## Schema

A valid `*_expt.md` file must contain the following top-level headers. It should be written in standard Markdown.

### 1. The Goal
A clear, 1-2 sentence definition of the optimization target.
- **Example:** "Minimize the Mean Absolute Percentage Error (MAPE) of TimesFM forecasting across the US Equity Region evaluation set."

### 2. Primary Metric
The single scalar value that determines success.
- **Must specify:** Direction of optimization (minimize or maximize).
- **Must specify:** Where this metric is logged (e.g., `results/metrics.json` -> `"mape"`).

### 3. State & Variables
The parameters the Researcher agent is allowed to modify.
- Variables should be listed with their current values and theoretical bounds.
- If the agent is editing a configuration file, specify the file path.
- If the agent is writing executable code, specify the target file and the interface it must implement.

### 4. Constraints (The Kill Gates)
Rules that must not be broken. The Evaluator will use these to immediately issue a `[TERMINATE]` signal.
- **Cost/Budget limits:** e.g., "Any trial taking longer than 10 minutes."
- **Resource limits:** e.g., "Cannot request more than 2 GPUs."
- **Hard boundaries:** e.g., "Do not modify the evaluation dataset."

### 5. Execution Environment
The shell commands required to run the simulation or training loop.
- Provide the exact bash script or Python command the Researcher should run.
- Specify the paths to all relevant logs generated by the run.
- Detail the telemetry available (e.g., "CPU utilization is logged in `logs/sys.csv`").

### 6. Historical Context (Optional)
Prior baseline knowledge.
- e.g., "The default TimesFM configuration achieves a MAPE of 0.28. Random search across learning rates typically fails to break 0.25."

## Example Template

```markdown
# [Project Name] Optimization Context

## 1. The Goal
[State goal clearly]

## 2. Primary Metric
- **Target:** [Minimize/Maximize] [Metric Name]
- **Location:** [File path to read metric from]

## 3. State & Variables
- Modifiable code is in `[filepath]`.
- Tunable hyperparameters are in `[filepath]`.

## 4. Constraints
- Do not modify `[filepath]`.
- Runs must complete in < X minutes.

## 5. Execution Environment
- Command to run: `./run.sh`
- Logs are written to: `logs/run.log`
```
