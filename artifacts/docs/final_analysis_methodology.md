# Final Analysis Methodology (Revised)

## 1. Overview

This document specifies the complete methodology for analyzing the results generated by `run_corrected_experiment.sh`. It has been **revised based on feedback from Turn 17** to ensure maximum statistical rigor. This plan will be implemented in the final analysis script.

## 2. Post-Execution Verification

As per the Methods Supervisor's request, the first step of the analysis is to verify the integrity of the experiment.

*   **Action:** The analysis script will compute the SHA256 checksum of the model artifacts used in the `experiments/arm_a_default_config` and `experiments/arm_b_robust_config` directories.
*   **Success Criterion:** The checksums must be identical.
*   **Outcome:** This will be reported as a "Verification Passed" or "Verification FAILED" check in the final report, confirming a single base model was used.

## 3. Statistical Significance Analysis (Revised)

This section is revised to address the Stats Supervisor's concern about applying standard tests to time-series data.

*   **Data:** The rolling evaluation produces a time series of forecast errors (e.g., Absolute Percentage Error) for each model at each forecast horizon.
*   **Previous Method (Invalid):** The original plan to use a paired t-test is insufficient as it assumes independence of observations, an assumption violated by the autocorrelated nature of forecast errors in a time-series context.
*   **Revised Method:** We will use the **Diebold-Mariano (DM) test**. This test is specifically designed to compare the predictive accuracy of two forecast models, accounting for the autocorrelation often present in forecast errors.
    *   **Implementation:** The DM test will be applied to the series of squared prediction errors for Arm A vs. Arm B.
    *   **Hypothesis:** The null hypothesis of the DM test is that the two models have the same forecast accuracy.
*   **Reporting:** We will report the DM statistic and its corresponding p-value. A p-value < 0.05 will provide statistically significant evidence that one model's forecast accuracy is superior to the other. This directly addresses the need for a method that respects the time-series nature of the data.

## 4. Uncertainty Quantification

The bootstrap method remains valid for estimating the magnitude of the performance difference.

*   **Method:** We will perform **bootstrap resampling** on the paired differences in MAPE scores between Arm A and Arm B.
*   **Reporting:** The final report will state the mean performance difference and its 95% confidence interval (e.g., "The Robust config improved MAPE by 0.5% (95% CI: [0.2%, 0.8%])").

## 5. Practical (Domain) Significance (Revised)

This section is revised to provide a quantitative justification for the practical significance threshold.

*   **Threshold Justification:** A typical management fee for an actively managed fund is around 1% of assets under management. A forecasting model that reduces error would need to generate alpha significantly greater than this fee to be considered valuable. A 0.5% reduction in MAPE is a conservative proxy for a meaningful cost-saving or alpha-generating capability. It represents a tangible improvement that could justify the adoption of the more complex 'Robust' configuration in an operational setting.
*   **Quantitative Criteria:** An improvement will be deemed "practically significant" if and only if:
    1.  The Diebold-Mariano test yields a p-value < 0.05.
    2.  The lower bound of the 95% bootstrap confidence interval for the MAPE improvement is **greater than 0.5%**.
*   **Qualitative Analysis:** This remains unchanged. The script will plot forecasts from the 5 best and 5 worst windows to provide qualitative insight into model behavior.
